# БелнипиAI — проверка ГОСТ на чертеже

Локальное веб-приложение: загрузите PDF или скан листа — система найдёт **ГОСТ, ОСТ, СТП, ТУ, СТБ** и проверит статус в NormaCS.

По умолчанию проверка выполняется только через **NormaCS**. Стройдок (`normy.stn.by`) временно отключён переменной `PDF_STN_LOOKUP=0`; обращения к `tnpa.by` в веб-пайплайне также отключены.

Чертежи **не отправляются в облако**: OCR выполняется в контейнере (Tesseract). В NormaCS уходят только **обозначения** нормативных документов.

## Требования

- [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Windows / macOS) или Docker Engine + Compose v2 (Linux)
- 8 ГБ RAM минимум (рекомендуется 12 ГБ)
- Свободный порт **8090**

## Проверка NormaCS по умолчанию

В `.env` добавьте учётные данные (этот файл не публикуется в Git):

```dotenv
PDF_NORMACS_LOOKUP=auto
PDF_NORMACS_BASE_URL=http://n.nanocad.ru:9999/normacsweb/
PDF_NORMACS_LOGIN=
PDF_NORMACS_PASSWORD=
PDF_NORMACS_TIMEOUT=30
PDF_NORMACS_RETRIES=1
PDF_NORMACS_BUDGET_MAX=3600
```

Заполните логин и пароль и пересоздайте web-контейнер:

```bash
docker compose -f docker-compose.yml -f docker-compose.fast.yml up -d --build --force-recreate web
```

Альтернатива: `/admin/` → «Интеграции» → добавьте сайт **NormaCS** с URL веб-интерфейса,
логином и паролем. Пароль хранится в PostgreSQL в зашифрованном виде. Включение `auto`
разрешает NormaCS при наличии учётных данных; `0` отключает интеграцию, `1` разрешает явно.
Проверка запускается автоматически для каждого PDF или скана. В API параметр `normacs=1`
теперь подразумевается по умолчанию; `normacs=0` оставлен для диагностического OCR без реестра.

Серверу нужен исходящий доступ к портам **9999** (веб-интерфейс) и **8888** (API,
адрес берётся из `config.json` веб-интерфейса). Текущий предоставленный сервер использует HTTP.
Проверка выполняется после OCR с отдельным бюджетом.
ГОСТ/ГОСТ Р/СНиП проверяются первыми. `PDF_NORMACS_TIMEOUT` ограничивает один HTTP-запрос,
`PDF_NORMACS_RETRIES` (0–2, по умолчанию 1) задаёт повторы временно неудачных запросов чтения.
Бюджет одного документа и всей партии учитывает повторы и ограничен
`PDF_NORMACS_BUDGET_MAX`. Таймаут не выдаётся за отсутствие или отмену норматива.
POST авторизации после потерянного ответа не повторяется, чтобы не занимать дополнительные
лицензии. При HTTP 401/403 во время чтения сессия восстанавливается один раз.
Поиск не запрашивает ненужный общий COUNT совпадений. Если три проверки подряд не проходят,
короткий контрольный запрос проверяет API: при подтверждённой недоступности оставшиеся
документы получают статус «Не проверен: NormaCS недоступен», а не «Не найден».
Причины ошибок видны в таблице и PDF. Веб-страница на 9999 не заменяет API на 8888:
если API недоступен, нужно восстановить сеть/работу сервера NormaCS; увеличение таймаута
или повторный OCR это не исправляют.
Тип, номер и год документа сопоставляются точно; ГОСТ и ГОСТ Р не смешиваются.
Если без года найдено несколько редакций, программа просит уточнить год.

В новых отчётах и скачиваемой PDF-таблице остаются колонки **NormaCS** и **Статус NormaCS (РФ)** без колонок Стройдока.
«Частично действует» не заменяется на «актуален». Статусы показываются по текущей карточке РФ,
история и условия применения доступны в подсказке статуса и в ссылке на карточку.
При отключённом Стройдоке поле исторической даты скрыто: NormaCS показывает текущий статус.

Проверка соединения без вывода пароля:

```bash
docker compose exec -T web python scripts/check_normacs.py
# с отдельной проверкой доступности веб-порта и API
docker compose exec -T web python scripts/check_normacs.py --diagnose
```

### Долгая обработка и потеря связи

Проверка нормативов выполняется фоновой задачей сервера. Закрытие вкладки или разрыв
SSE-соединения не удаляет исходный PDF и не останавливает обработку. Отчёт сохраняется
в PostgreSQL до отправки признака завершения браузеру. После потери связи интерфейс
получает состояние задачи короткими запросами; открытие того же чата восстанавливает
ожидание результата без повторной загрузки файла. В одном чате допускается одна активная проверка.

Кнопка остановки прерывает получение ответа, но серверная проверка продолжается.
Перезапуск **самого web-контейнера** прерывает незавершённые задачи; уже сохранённые
отчёты остаются в базе. Временный файл удаляется после завершения обработки.
В логах есть ID задачи/чата, запись сохранения отчёта, причины ошибок NormaCS и итоговые
количества найденных/ошибочных/пропущенных документов.

## Админ-панель (`/admin`)

Отдельный служебный интерфейс для IT/администраторов. **На главной странице приложения ссылки на админку нет** — URL передают только ответственным людям.

| URL | Назначение |
|-----|------------|
| http://localhost:8090/ | Основное приложение (проверка ГОСТ) |
| http://localhost:8090/admin/ | Настройка организации |

Админка и приложение — **один процесс** (`app.py`), **одна база** PostgreSQL. Настройки из админки сразу читает основной код:

```
/admin  →  PostgreSQL (tenant_settings, tenant_integrations)
                ↓
belener/config.py  →  stn_login(), stn_password(), stn_base_url()
                ↓
belener/stn_lookup.py  →  проверка актуальности на normy.stn.by
```

| Что настраивается в админке | Где используется |
|-----------------------------|------------------|
| **Интеграции → NormaCS** (логин/пароль, URL) | Проверка актуальности ГОСТ/СП в основном приложении |
| **Интеграции → Стройдок** (логин/пароль, URL) | Сохранено для возможного возврата; сейчас отключено флагом |
| **Active Directory** | Вход только в `/admin` (список администраторов панели) |
| Параметры OCR, бюджеты, модели | По-прежнему в `.env` |

**Приоритет учётных данных Стройдok:** запись в админке (БД) → legacy в БД → переменные `PDF_STN_*` в `.env`.

### Первый запуск админки

1. Поднимите стек (см. [Быстрый старт](#быстрый-старт-клон--docker--тест)).
2. Откройте **http://localhost:8090/admin/** — мастер первоначальной настройки.
3. Шаг **Active Directory:** LDAP URI, Base DN, служебная учётка, список администраторов панели.
4. Войдите под своей учётной записью AD.
5. Вкладка **Интеграции** → добавьте **NormaCS** с логином и паролем → **Проверить** → **Сохранить**.
6. На главной странице (http://localhost:8090) загрузите PDF — статус будет проверяться в NormaCS с учётными данными из админки.

Пересборка после изменений кода:

```bash
docker compose up -d --build web
```

Сброс только настроек AD (мастер настройки снова откроется):

```bash
docker compose exec db psql -U belener -d belnipiai -c "DELETE FROM tenant_settings WHERE key LIKE 'ad.%';"
```

## Настройка `.env`

| Переменная | Назначение |
|------------|------------|
| `WEB_PORT` | Порт веб-интерфейса (по умолчанию 8090) |
| `PDF_STN_LOGIN` / `PDF_STN_PASSWORD` | Учётная запись ИПС (запасной вариант, если не задано в админке) |
| `PDF_STN_LOOKUP` | `0` — не обращаться к Стройдоку; `1` — вернуть его проверку |
| `PDF_TILE_OCR_DPI` | Качество OCR (320 — баланс скорость/точность) |
| `PDF_GOST_CHECK_BUDGET` | Базовый лимит OCR (сек.) на 1 лист (по умолчанию 600) |
| `PDF_GOST_EXTRA_PER_PAGE_SEC` | Добавка с/лист для коротких томов; далее ступени 85%/72% (не ниже 22/20 с) |
| `PDF_GOST_CHECK_BUDGET_MAX` | Потолок OCR (по умолчанию 14400 ≈ 4 ч; тома 200+ листов) |
| `PDF_STN_BATCH_BUDGET` | Минимальное отдельное окно Стройдока после завершения OCR |
| `PDF_TILE_OCR_MAX_PAGES` | `0` — все листы; иначе лимит листов |
| `BELENER_SSD_ROOT` | Путь к кэшу на SSD (по умолчанию `G:/BelenerCache`) |
| `PDF_ZONE_CACHE` | `1` — кэш PNG-тайлов на SSD между запусками |

После изменения `.env`:

```powershell
.\scripts\up_gost_stack.ps1 -Recreate -NoBuild
```

## Просмотр результатов

- Кнопка в верхней панели переключает светлую и тёмную тему. Выбор сохраняется в этом браузере.
- Документ расположен слева, список нормативов и карточка выбранного обозначения — справа.
  На узком экране блоки располагаются друг под другом.
- Можно переключать список и карточки, перейти к упоминанию по номеру листа,
  увеличить лист и нажать «К упоминанию» для приближения выбранного выделения.
- Жёлтый цвет показывает найденный текст, зелёный — выбранный норматив, **не его актуальность**.
  Новые отчёты показывают статус NormaCS; старые отчёты с результатами Стройдока не изменяются. Ошибка связи или отсутствие
  ответа не выдаются за отмену документа.
- Для новых проверок подсветку можно выключить; нажатие на выделение открывает карточку.
  Старые отчёты остаются доступными, но для интерактивных выделений их нужно проверить заново.
- Экспорт PDF использует исходную таблицу отчёта. Переключение темы или вида не запускает OCR
  и не отправляет запросы в реестры. Неактивные листы новых отчётов загружаются по необходимости.

## Приватность

- `PDF_LOCAL_ONLY=1` — без облачных LLM и vision
- `PDF_REPORT_LLM=0` — отчёт только из OCR и парсера
- На normy.stn.by передаются коды документов (ГОСТ 10704-91 и т.п.), не изображения чертежа
- **Номера ГОСТ не подставляются** из «ожидаемого списка»: в отчёт попадает только то, что прочитано с листа; спорные OCR-варианты разрешаются голосованием по тайлам, без таблицы замен
